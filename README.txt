مساعد ilogia الدراسي — Supabase + Gemini
=========================================
1) أضف مفتاح Gemini إلى Edge Function Secrets في مشروع Supabase المضبوط في
   config.js. الاسم المفضّل GEMINI_API_KEY، ويُقبل أيضًا الاسم الحالي gemini api.
2) الدالة تتحقق من جلسة Supabase بنفسها؛ لذلك لا تحذف التحقق اليدوي داخل الكود.
   إعداد verify_jwt=false يسمح بمرور طلب OPTIONS الخاص بـ CORS إلى الدالة.
   انشر الدالة من مجلد المشروع لإرسال إعداد CORS الجديد:
   supabase functions deploy ilogia-ai
3) تأكد أن تسجيل البريد وكلمة المرور مفعّل في Supabase Auth.
4) ارفع ملفات الواجهة الثابتة إلى الاستضافة.

عند استخدام المساعد، تقرأ الدالة بيانات الطالب المسجّل فقط من ملفه وخطته
وبطاقاته واختباراته وتقدّمه الدراسي، باستخدام جلسة Supabase وسياسات RLS.
تُرسل خلاصة هذه البيانات إلى Gemini مع السؤال، ولا يُستخدم مفتاح الخدمة
لتجاوز صلاحيات قاعدة البيانات. إذا كان جدول غير متاح أو لا يحتوي بيانات،
يُوضح المساعد ذلك بدل اختلاق نتائج.
عند ذكر خدمات ilogia، يعرض المساعد أسماءها كرابط قابل للنقر بدل إظهار
عنوان الرابط كنص، كما تحوّل الواجهة عناوين هذه الخدمات إلى أسماء تلقائيًا.

التطبيق يستخدم Supabase Auth وEdge Functions مباشرة. لا يحتاج خادم PHP
ولا إعداد قاعدة بيانات منفصلة. مفتاح Gemini يبقى داخل Supabase ولا يوضع
في config.js. عند ضغط النموذج الأساسي، تحاول الدالة استخدام gemini-3.5-flash-lite
تلقائيًا كبديل.
